# 实时风控系统方案

## 一、背景与挑战
某互金平台交易峰值 5000 TPS,欺诈手段升级快(团伙、养号、薅羊毛),原有规则引擎 T+1 离线跑批,等发现损失已发生。需要毫秒级实时拦截。

## 二、方案目标
- 风险决策延迟 < 100ms(P99)
- 欺诈拦截召回率 ≥ 92%,误杀率 < 0.5%
- 规则可热更新,新策略上线 < 1 小时
- 支持事中拦截 + 事后回溯

## 三、总体架构
「实时特征 + 规则引擎 + 模型评分 + 决策编排」。事件流入 Kafka,Flink 实时算特征,规则引擎(Drools/自研)+ 机器学习模型并行打分,决策引擎融合输出放行/拦截/复核。

## 四、技术选型
- 流计算:Flink(实时特征、滑动窗口)
- 特征库:Redis + HBase(实时/离线特征)
- 模型:XGBoost/GBDT + 图算法(团伙识别)
- 规则:可视化规则引擎,支持灰度
- 名单:实时黑白灰名单

## 五、核心功能模块
1. 实时特征计算(频次、金额、设备、地理)
2. 规则引擎(可配置、可灰度、可回滚)
3. 模型评分(欺诈分、信用分)
4. 关系图谱(团伙、设备共用、资金链)
5. 决策编排 + 人工复核工作台

## 六、实施步骤
① 实时链路与特征平台(6 周);② 规则引擎 + 名单(4 周);③ 模型与图谱(8 周);④ 决策编排与策略运营。

## 七、关键指标(KPI)
召回率、误杀率、决策延迟、规则覆盖、案件挽损金额、策略迭代周期。

## 八、风险与对策
- 误杀影响体验 → 分级处置(拦截/验证码/复核)
- 模型漂移 → 持续监控 + 定期重训
- 对抗升级 → 图谱 + 无监督异常检测补位

## 九、成本估算
建设约 180 万;年运营约 50 万。价值直接体现为挽损,通常 6 个月内挽损额即覆盖投入。

## 十、方案优势与适用场景
适用于支付、信贷、电商、游戏等高频交易风险场景。优势:实时、可灰度、可解释。需要持续的策略运营团队,不是一锤子买卖。
