# 企业数据中台建设方案

## 一、背景与挑战
集团有 ERP、CRM、MES、电商、财务等 20+ 套系统,数据孤岛严重,口径不一(同一"销售额"各系统差异达 15%)。报表靠人工 Excel 拉取,T+3 才能出数,管理层无法实时决策。

## 二、方案目标
- 统一指标口径,核心指标差异 < 1%
- 数据时效从 T+3 提升到准实时(分钟级)
- 自助分析覆盖 80% 常规报表需求
- 数据复用率提升,新报表交付从 2 周缩短到 2 天

## 三、总体架构
分「采集—存储—计算—服务」四层 + 数据治理贯穿。采集用 CDC + 批流一体;存储分 ODS/DWD/DWS/ADS 分层数仓;计算用离线(Spark)+ 实时(Flink);服务层提供统一指标 API + 自助 BI + 数据地图。

## 四、技术选型
- 采集:Flink CDC / DataX
- 存储:Hive + ClickHouse(OLAP)+ Kafka(实时)
- 调度:DolphinScheduler
- 指标:统一指标平台(维度/口径登记)
- BI:自研 + Superset

## 五、核心功能模块
1. 数据接入与 CDC 同步
2. 分层数仓建模(维度建模 Kimball)
3. 统一指标管理(原子/派生指标、口径登记)
4. 数据资产地图与血缘
5. 自助分析 + 数据 API 服务

## 六、实施步骤
① 数据摸底与标准制定(4 周);② 数仓分层 + 核心域接入(销售/财务,8 周);③ 指标平台 + BI(6 周);④ 全域扩展与治理常态化。

## 七、关键指标(KPI)
指标覆盖率、口径一致性、数据时效、任务成功率、数据复用率、血缘完整度。

## 八、风险与对策
- 口径扯皮 → 成立数据委员会,口径由业务+数据共同签署
- 任务雪崩 → 分层调度 + 基线告警 + 重跑机制
- 治理流于形式 → 把数据质量纳入部门考核

## 九、成本估算
一次性约 220 万(平台 + 实施);年运营约 60 万。价值在决策提效与人力释放,12-18 个月见效。

## 十、方案优势与适用场景
适用于系统多、数据散、需要统一经营分析的中大型集团。优势:口径统一、时效大幅提升、数据资产化。前提是组织愿意推进数据治理,否则技术再好也落不了地。
