# 商用级优化方案 · 知识库问答(RAG) + 智能问数(NL2SQL) + 图表可视化

> 目标:把三大核心模块从"受控可用"提升到"可量化、可回归、可无人值守"的商用级。
> 原则:**先建度量,再谈优化**。每一项优化都必须有可量化的验收指标,否则不算完成。
> 标注:✅ 本期已实现 / 🔧 待优化 / ⭐ 高优先(P0)

---

## 〇、贯穿全局:评测与质量保障体系(商用级的前提)

没有评测体系,所有"优化"都是拍脑袋。这一节是其余所有优化的**度量底座**,必须最先落地。

### 0.1 黄金测试集(Golden Set)
- 每个业务库/知识库建 **50–100 条**代表性问答,覆盖:简单事实、跨文档综合、跨表 JOIN、聚合统计、模糊口语、歧义、边界(查不到/超大结果)。
- 每条标注:问题、期望要点/期望 SQL 或期望结果、期望来源文档、难度等级。
- 来源:真实业务问题优先,严禁只用规整造的测试数据自欺。

### 0.2 量化指标(行业标准)
| 模块 | 核心指标 | 商用级目标 |
|------|---------|-----------|
| RAG 检索 | Context Recall(召回覆盖)、Context Precision、MRR@10、nDCG@10 | Recall ≥ 0.85,Precision ≥ 0.7 |
| RAG 生成 | Faithfulness(忠实度/防幻觉)、Answer Relevance、引用正确率 | Faithfulness ≥ 0.9,引用正确率 ≥ 0.95 |
| NL2SQL | Execution Accuracy(执行结果正确率 EX)、SQL 有效率、0 行率 | EX ≥ 0.85,有效率 ≥ 0.98 |
| 可视化 | 图型命中率、可读性人工评分 | 图型命中 ≥ 0.85 |
| 性能 | 首 token 延迟、P95 总时长 | 首 token < 1.5s,P95 < 8s |

### 0.3 评测流水线
- **自动评测脚本**:对 Golden Set 批量跑,用 RAGAS 式方法(LLM-as-judge + 规则)算上表指标,出报告。
- **回归门禁**:每次改提示词/检索参数/模型,必须先跑评测,指标不退化才允许上线。
- **线上监控**:命中率、空答率、0 行率、坏案例率、点踩率、P95 延迟,做大盘 + 阈值告警。
- **坏案例闭环**:点踩/低分问答自动入"待优化"队列,人工复核 → 进 Golden Set 或修知识/口径。

> 🔧 当前缺失,**P0 必建**。这是从"看着还行"到"可证明达标"的分水岭。

## 一、知识库问答(RAG)优化方案

### 1.1 文档切片(Chunking)质量 ⭐P0
- **现状**:基础切片 + 邻居扩展 ✅;但切片策略对表格/代码/标题层级保护不足。
- **优化**:
  - 标题感知 + 语义切分(按章节/语义边界,而非定长硬切)
  - 父子分块(Parent-Child):命中小块、喂大块,兼顾精准与上下文完整
  - 表格/列表/代码块**整体保护**,不被拦腰切断
  - 重叠窗口(overlap)防边界信息丢失
- **验收**:切片完整率 ≥ 95%(无断句/断表);命中片人工可读性评分 ≥ 4/5。

### 1.2 检索召回增强 ⭐P0
- **现状**:向量 + BM25 + RRF 融合 + 重排 + 相关性过滤 ✅;查询改写 ✅;可选知识图谱 ✅。
- **优化**:
  - 多查询改写 / 子问题分解 / HyDE(假设性答案再检索),提升长尾召回
  - 元数据过滤(按分类/时间/文档类型)缩小噪声
  - 混合权重(向量 vs BM25)按问题类型自适应
- **验收**:Context Recall ≥ 0.85,MRR@10 ≥ 0.7(对照 Golden Set)。

### 1.3 生成忠实度与防幻觉 ⭐P0
- **现状**:强制基于检索作答 + 反思(reflection)+ 兜底"资料不足" ✅。
- **优化**:
  - Faithfulness 自检:生成后校验每个论断是否有出处,无出处的标注或删除
  - 引用可点击 + 精确到段落(溯源体验)
  - 结构化输出模板(按问题类型)
- **验收**:Faithfulness ≥ 0.9;引用正确率 ≥ 0.95;幻觉坏案例 < 2%。

### 1.4 多文档/长文档综合 ✅+🔧
- **现状**:深度总结模式(高召回 + 结论先行 + 跨文档关联 + 专业结构化)✅(本期)。
- **优化**:
  - Map-Reduce:每文档先摘要,再合成,突破上下文长度上限(超大文档集)
  - 自动识别"综合/对比/全量"意图 + 显式「深度总结」开关 ✅
- **验收**:10+ 长文档总结的"要点覆盖率 ≥ 90%",人工专业度评分 ≥ 4/5。

### 1.5 多轮对话 ✅+🔧
- **现状**:历史改写(query rewriter)✅。
- **优化**:指代消解强化、会话级记忆(用户偏好/已澄清事实)、跟进问题不丢上下文。
- **验收**:多轮跟进问题正确率 ≥ 0.8。

### 1.6 增量索引与时效 🔧
- **优化**:文档更新/删除时增量重建向量,避免全量重跑;失效文档及时下线。
- **验收**:文档更新到可问答延迟 < 5 分钟;无"已删文档仍被引用"。

## 二、智能问数(NL2SQL)优化方案

### 2.1 Schema 表征增强 ⭐P0
- **现状**:表/列语义 + 样例值 ✅;表关系命名推断 ✅(本期);强制聚合 ✅。
- **优化**:
  - 读取**真实外键**补充命名推断(JOIN 更准)
  - 列基数/枚举值/数据类型入提示词
  - **业务术语词典**(同义词→表/列/值映射,如"营收"=revenue)
  - **Few-shot 示例库**:每数据源沉淀若干 问题→正确SQL 范例
- **验收**:跨表 JOIN 问题 EX ≥ 0.8。

### 2.2 值链接(Entity Linking)⭐P0
- **现状**:样例值注入 ✅(缓解字面不匹配);但仍非精确链接。
- **优化**:对过滤条件里的值,先在真实列值上做模糊/向量匹配,找到真实取值再写进 SQL(解决"生理学"↔"生理滚动2")。
- **验收**:含命名实体过滤的问题,0 行率下降 ≥ 50%。

### 2.3 自纠错闭环(Self-Correction)⭐P0 🔧
- **现状**:单轮生成,无重试。
- **优化**:
  - 执行前:EXPLAIN/dry-run 校验列存在性与语法
  - 执行后:报错或 0 行 → 把错误/空结果回喂 LLM,放宽条件/改 JOIN 重写,最多 N 轮
- **验收**:SQL 有效率 ≥ 0.98;可修复的 0 行案例修复率 ≥ 60%。

### 2.4 语义/指标层(护城河,P1)🔧
- **优化**:预定义指标(口径/维度/过滤),问题先映射到指标再生成 SQL,而非每次裸生成。
- **价值**:口径统一、准确度质变,是商业智能问数的核心壁垒。
- **验收**:纳入指标层的指标类问题 EX ≥ 0.95,口径 100% 一致。

### 2.5 歧义澄清与复杂分解 🔧
- **优化**:歧义问题主动反问(复用现有 clarify 机制);复杂问题拆成多步查询再合成。
- **验收**:歧义问题"先澄清再答"比例提升,误答率下降。

### 2.6 安全/治理/大结果 ✅
- **现状**:只读 + SqlGuard + 超时 + 强制 LIMIT + ACL + 审计 ✅;截断诚实标注 + 强制聚合 ✅(本期);表结构定时同步 + 删表自动禁用 ✅(本期)。
- **优化(可选)**:行级权限、查询成本预估、慢查询治理。

## 三、图表/可视化优化方案

### 3.1 图型智能推荐 ⭐P0
- **现状**:LLM 选 chartType(bar/line/pie)+ 手动切换 ✅;但命中不稳。
- **优化**:基于数据形态(维度数/度量数/是否时间序列/基数)用**规则 + LLM**联合定型,规则兜底。
- **验收**:图型命中率 ≥ 0.85(人工评)。

### 3.2 图型扩展 🔧
- **优化**:堆叠柱、分组柱、双轴、散点、漏斗、热力、地图(地理维度)、KPI 卡。
- **验收**:覆盖常见 8+ 图型,复杂数据有合适表达。

### 3.3 二次分析能力 ⭐P0(对标商业产品最缺的)🔧
- **优化**:图表下「数据解读 / 归因分析 / 智能预测」三按钮,复用已查结果再调 LLM,流式返回。
- **验收**:解读结论与数据一致、有洞察(人工评分 ≥ 4/5)。

### 3.4 大数据展示 🔧
- **优化**:服务端聚合/下采样后再渲染;明确标注"基于聚合/前 N 行";避免前端卡顿与误导。
- **验收**:万级以上结果不卡顿,结论不因截断失真。

### 3.5 交互与导出 ✅+🔧
- **现状**:PNG/CSV 下载 + 图表类型切换 ✅(本期)。
- **优化**:维度钻取/筛选、全屏、Excel 导出、高清图导出、配色与数值格式规范、空/异常态友好。
- **验收**:导出可用率 100%;可读性人工评分 ≥ 4/5。

## 四、性能与体验(横切)

- **首 token 提速**:占位即时反馈 + 检索/查库并行(已并行)+ 必要时小模型预答。目标首 token < 1.5s。
- **语义缓存**:高频相同/相似问题缓存答案与检索结果,降延迟降成本。
- **流式渲染**:Markdown 边出边渲染 ✅(本期)。
- **模型分级**:简单问题用快/小模型,复杂综合用强模型,平衡速度与质量。

## 五、分期路线图(建议)

### P0 · 第一期(达标线,约 3–4 周)—— "可证明达标"
1. **评测体系**(Golden Set + 自动评测 + 回归门禁)← 一切的前提
2. RAG:切片质量、召回增强、忠实度自检
3. NL2SQL:值链接、自纠错闭环、真实外键
4. 可视化:图型智能推荐、数据解读/归因/预测三按钮
5. 性能:首 token 提速

> 出口标准:Golden Set 上 RAG Faithfulness ≥ 0.9、NL2SQL EX ≥ 0.85、图型命中 ≥ 0.85,且接入回归门禁。

### P1 · 第二期(拉开差距,约 4–6 周)—— "护城河"
1. NL2SQL **语义/指标层**
2. RAG **Map-Reduce** 长文档综合 + 多轮记忆
3. 可视化图型扩展 + 大数据聚合展示
4. 语义缓存、模型分级

### P2 · 第三期(精细化运营)
1. 坏案例闭环 → 自动进化(反馈学习)
2. 线上监控大盘 + 告警
3. 增量索引、行级权限等治理增强
